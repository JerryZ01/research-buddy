# 编辑型文章生成管线

## 目标

把文章质量的主要控制点从「持续堆叠写作 Prompt」前移到证据、判断和编辑任务。管线必须满足：

- 具体断言能追溯到真实搜索证据。
- 写作前先确定文章的唯一核心判断、范围和章节职责。
- 审校输出是可执行的局部修改，不是再次整篇重写。
- 任何新节点失败时可降级，不阻断现有出稿能力。

## 目标流程

```text
问题拆解 -> 搜索 -> 证据充分性验证
                         |
                         v
              证据账本 + 编辑简报
                         |
                         v
                      文章初稿
                         |
                         v
          论证审校 -> 语言审校 -> 事实审校
                         |
                         v
                    局部修改后定稿
```

## 分阶段实施

### 阶段 1：证据账本与编辑简报（已接入）

`editorial_planner` 位于 `validator` 和 `synthesizer` 之间。

证据账本由确定性代码构建：

- 以规范化 URL 去重，不另外调用模型。
- 保留原始证据摘录，不让 LLM 预先改写证据。
- 合并关联子问题、证据验证状态和已知冲突。
- 使用 `E1`、`E2` 等稳定编号，编辑简报和写作输入共用同一映射。

编辑简报产出：文章意图、目标读者、核心判断、包含/排除范围、必讲要点、章节职责、证据映射、禁止断言和收束方式。代码会删除幻觉证据编号；简报结构不完整时整体丢弃，降级到原有写作流程。

这一阶段每次进入初稿前新增一次非流式 LLM 调用。反思只要求用当前证据改写时复用已有简报；只有追加搜索经过验证后才重建账本和简报。

### 阶段 2：事实审校（已接入）

对初稿中的数字、工具行为、因果关系和具体建议做断言级检查。审校器只能返回「原文精确片段 + 替换文本 + 支持证据原句」。代码验证原文和证据原句都真实存在后才应用。

生产策略：

- 默认扫描 1 轮；没有问题时只新增 1 次 LLM 调用。
- 非空替换必须通过独立证据复核，因此最多新增 2 次调用；纯删除不引入事实，不走复核。
- 上下文守卫会拒绝制造悬空连词、标点或相邻重复的局部修改。
- 修订稿通过 `report_reset` 清空前端初稿，再分块推送，界面与最终状态一致。
- 节点或复核失败时 fail open，保留原稿或已完成的可验证编辑。

### 阶段 3：论证审校（待实现）

检查每节是否完成编辑简报中的职责，是否存在结论跳跃、重复论证、忽略冲突证据或“证据与结论之间缺一步”。该节点不负责事实补全，只调整论证或明确降低结论强度。

### 阶段 4：语言审校（已先行接入）

处理「不是……而是……」、空泛转折、读者指令、仪式化总结和重复段首连接词。当前先接在初稿与事实审校之间；阶段 3 完成后，论证审校将插入语言审校之前，事实审校保持最后兜底。

生产策略：

- 代码先扫描高置信模板句；没有候选时不调用模型。
- 模型只能改写扫描出的完整原句，最多 8 处，不能自行选择其他正文。
- 数字、引用编号、URL 和英文专名必须在修改前后完全一致，否则代码拒绝应用。
- 标题、列表、表格、代码块和参考文献不进入候选集。
- 前端节点详情展示修改前、修改后、问题类型和原因，便于直接检查效果。
- 语言节点失败时保留当前文章；其后仍经过事实审校。
- 写作规划通常只保留 2-4 个核心章节；三级小标题只用于长章节内部的独立层次。
- 标题禁止装饰性比喻、拟人、口号和悬念。代码会识别高置信比喻标题并触发直接标题重写，反思节点负责最终兜底。

### 图片资产与插入（已优化）

- 视觉选图下载成功后按内容哈希缓存到本地，正文优先使用同源 `/media/research-images/` 地址，避免第三方防盗链和临时 URL 失效。
- 水印是选图硬门槛，分两道检查：
  1. **选图时**：prompt 要求模型先逐字抄写画面上的叠加内容（署名、网址、平台名、版权、二维码、平铺水印等）到 `overlay` 字段，再判定 `watermark_status`——只有 `overlay` 为空串才允许填 `none`；`overlay` 非空或状态非 `none` 一律拒绝。
  2. **入选后**：每张入选图再单独发一次一图一问的复核（`VERIFY_WATERMARK_PROMPT`），只有复核抄不出任何叠加内容才允许缓存和入文。
- 之所以要两道：封闭式提问（「有没有水印？none/present/uncertain」）会被视觉模型橡皮图章式地答成 `none`——实测带「知乎 @北方的郎」署名的图在复合任务里被判 `none`，而单独问「抄写叠加内容」时同一模型能稳定读出。改成「先抄写、再判定」的生成式任务后，模型必须真的看画面。
- 复核 fail-closed：调用失败重试 3 次仍失败、输出不合格式、抄出任何叠加内容，都按有水印处理，拒绝该图。
- 素材库/站点水印、作者署名叠字、账号 ID、二维码、版权叠印及疑似水印全部拒绝；图表自带的坐标轴/图例/标题/数据标注、产品界面自带品牌 Logo 不算。
- 存量缓存用 `scripts/audit_image_watermarks.py` 复查：只删**硬信号**（作者署名/账号、来源域名、素材库与版权标记、重复出现的营销短语），抄出的内容若属于图表或界面本身（架构图分层标签、PPT 页标题、免责声明）只报告不删。删图前用 `--purge-articles` 清掉已生成文章里对它的引用，避免留下破图。
- 写作模型只看到 `[[IMAGE_n]]` 占位符，不再接触或手抄图片 URL；代码在生成后恢复准确 Markdown。
- 兼容修复模型误写的普通图片链接和历史篡改 URL，未知图片直接删除。
- 配图预算按编辑简报章节数动态计算，通常为每个核心章节提供最多 2 张候选；单一主题保留最多 3 张候选。视觉模型先筛相关性，写作者再按内容需要决定实际使用数量，并按子问题轮询选图，避免前几个章节占完配额。
- 图片加载失败时前端隐藏整个插图容器，不留下破图、题注或残缺链接。

### 搜图与生图的混合配图（已落地）

配图有两种来源，由 `image_planner` 节点在写作前逐个子问题判定。**LLM 只判定「需求类型」，图源由代码查表推导**，不把 `kind` 交给模型输出——早期版本让模型同时给出 `need` 和 `kind`，实测出现「reason 写必须搜索官方真实图表、kind 却给 generate」的自相矛盾，生成出一堆通用图标拼盘。

| need | 含义 | 图源 | 搜不到时 |
| --- | --- | --- | --- |
| `real_asset` | 产品界面、官方公告、定价页、人物、现场照片、官方架构图 | 搜图 | **不配图** |
| `data_viz` | 真实数值的对比、趋势、基准成绩 | 搜图 | **不配图** |
| `structure` | 流程图、架构图、模块关系、状态机、时间线 | 生图 | — |
| `decorative` | 好看的配图、概念意象、章节头图 | 生图 | — |
| `none` | 无需配图 | — | — |

- **前两类绝不生图兜底**。生成一张「看起来像官方公告」或「看起来像基准成绩柱状图」的图，等于伪造证据——图上没有真实数据却像真的。这类位置宁可不配图。早期版本把生图当作搜图失败兜底，是设计错误。
- 生图提示词按需求类型分两套：`structure` 要求结构准确、中文标签齐全（实测 gpt-image-2.5 中文渲染准确，标签是技术图传递信息的主要手段）；`decorative` 不要求标签，重在意象与视觉美感。
- 规划器写出的 `want` 必须是可执行的构图指令：分层/分栏、每个元素的具体形态、要写的标签文字、配色与线宽。只写「一张展示 XX 的示意图」会得到通用图标拼盘。
- 生成的图一律在 alt/题注前加「示意图：」，写作 prompt 中标注为「只能用于解释机制/流程，不可当作事实证据」，并在写作规范里禁止「如图所示，某公司市占率……」这类把示意图当证据的写法。
- `MAX_GENERATED_IMAGES` 控制单篇生图上限（默认 4），生图比搜图慢（单张 30~50s）且贵。

### 配图终审（文章写完之后）

选图阶段只能看到「单张图 + 子问题」，看不到图最终落在哪一段、正文说了什么。`image_reviewer` 节点接在 `synthesizer` 之后、`language_editor` 之前，逐图复核**图片与它所在段落**是否匹配。

判定与动作：

| 情形 | 动作 |
| --- | --- |
| 图文数字明显冲突（正文写 65.7%，图上别的数字） | 删图 |
| 图与所在段落讨论的内容明显不相关 | 删图 |
| 题注不准确 | 改题注（≤40 字），保留图 |
| 看不清 / 拿不准 / 调用失败 | **保留** |

三条设计原则，决定这一层是正向收益还是负资产：

1. **只做减法**。只有 keep / drop / fix_alt，不新增图、不重新搜图——否则会变成第二个选图器，成本失控。
2. **不确定就保留**。删图是不可逆的净损失，留一张弱图只是轻微减分。视觉不可用、调用失败、输出不可解析、数字看不清，一律保留。
3. **矛盾删图，不改正文**。图片是外部素材，正文的证据链由更早的节点负责；为迁就一张来源不明的图去改正文数字是本末倒置，还可能引入事实错误。

其他实现要点：

- 反思回环时按 URL 去重，已审过的图不再重审（视觉接口并发弱，重审会明显拖慢出稿）。`image_review.passed` / `dropped` / `alt_fixes` 跨轮累积，`selected_images` 同步剔除已删图，避免下一轮 synthesizer 复用又把图放回正文。
- 整层任何异常都降级为「全部保留」，绝不阻断出稿。
- 视觉模型未配置时整层跳过。

### 反思最佳稿（已优化）

反思循环持续保存历史最佳稿。硬校验通过的稿件优先于含未知 URL、模板问题或未解决缺口的稿件，同一层级再比较完整性、准确性和清晰度分数。最后一轮变差或解析失败时恢复历史最佳稿，不再无条件交付最后一次重写。

## 暂不做的事

- 不把反思轮数继续当作主要质量手段。
- 不让一个综合评审 Prompt 同时承担事实、论证和文风审校。
- 不在没有证据支持时使用模型训练知识补全搜索结果。
- 不在本阶段启动文章质量回归任务。
