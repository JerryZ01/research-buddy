# 项目概述

![项目全景](./images/02-project-overview.png)

## 项目目标

Research Buddy 是一个基于 LangGraph + Langfuse 的深度研究 Agent。用户输入一个问题，系统自动完成「拆解 → 搜索 → 验证 → 写作 → 反思」的完整链路，最终产出一篇带来源引用、置信度评估、经语言与事实审校的结构化研究报告（文章）。

核心定位是**以证据为基础**：搜索证据与模型判断分离，零证据时不允许模型直接凭内部知识出稿，从而保证文章可追溯、可信赖。

## 核心用户

- **需要快速获得深度研究报告的用户**：输入一个问题即可得到带来源引用的成稿，无需手工搜集、交叉比对资料。
- **需要文章/内容批量生产的用户**：通过知识研究与定时追踪，对指定主题持续产出、增量更新和推送变化。
- **追求内容质量与可审计性的团队**：利用编辑简报、语言/事实审校、独立反思 Judge、文章素材库与 A/B 回归评测，把文章质量从「靠单次 Prompt」提升为「分层控制」。

## 系统边界

系统与以下外部服务交互（业务视角）：

- **LLM（OpenAI 兼容 API）:** 规划、写作、编辑、反思等所有模型判断；支持任何 OpenAI 兼容中转站（讯飞 MaaS、硅基流动、DeepSeek 等）。
- **Tavily Search API:** 面向 AI Agent 优化的搜索服务，为研究提供证据来源（必填依赖）。
- **Langfuse:** 可观测性平台，用于全链路 Trace、评分与 Prompt 版本管理。
- **通知 Webhook:** 可选，支持企业微信 / 钉钉 / Telegram 机器人，用于追踪变化的推送通知。
- **视觉模型（可选）:** 独立配置的 vision 模型，用于图片相关性、可用性与水印筛选。

## 核心业务流程

1. **普通研究**：`问题 → 规划拆解 → 并行搜索 → 证据验证 → 编辑简报 → 写作 → 语言/事实审校 → 反思 → 输出成稿`。存在「证据闭环」和「成稿闭环」两个修正循环，搜索、反思、续写、图片均设预算，避免无界循环。

2. **知识研究（增量）**：在普通研究前后增加「知识召回」和「知识入库」节点，从历史报告召回已有事实与来源并去重，只规划缺失信息，最终把新报告与关键事实写入 SQLite 与 ChromaDB，形成版本链。

3. **人机交互（HITL）**：在搜索前中断让用户确认/编辑子问题，在反思前中断让用户审阅文章并添加修改要求，通过 `thread_id` 跨重启恢复会话。
